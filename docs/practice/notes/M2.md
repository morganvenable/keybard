# M2: Live · USB (plus the M0 lab view): implementation notes

Milestone M2 from [spec.md](../spec.md) §12 (§3.2, §3.3, §5.6, §6.5–§6.7, §9.3, §10), plus the M0 measurement view. Branch `feat/practice-trainer`, on top of M1b. Built overnight on 2026-10-09 **without hardware**: every board read in the tests is a scripted mock (`tests/practice/input/fakeBoard.ts`); nothing here has talked to a real board. Everything that needs the Mule is listed under "Needs Mule testing".

## Deviations from the spec, and why

1. **Candidate order around the input** (§9.3 says "latest first"): rules 1–3 try the edges that can lie before the input latest first, then edges seen after it earliest first. Pure latest-first let a step take the *next* press of the same key when it fell inside ε (a quick "ll"), leaving the second step inferred.
2. **Rule 3 on a hit keeps the character's path**: when the key pressed types something else under the keymap (the OS layout case), the hit keeps its primary path in `path` (so the character's stats still count) with the key actually pressed in `phys`. The packed layout rebuilds a hit's path from `phys`, so such a hit unpacks with the pressed key's path. Rare (it is the mismatch case); noted for M4, which shows that notice.
3. **Layer locked on drops keystrokes** like Caps Lock (no save, no advance); the spec says only "excluded from stats". Raised as **OWNER_Q12** (recommended yes; `false` counts them normally).
4. **A one-shot waiting for its key is not a locked layer**: the spec's rule ("no MO/LT/OSL held") would show the notice whenever OSL is tapped and the next key comes more than 300 ms later. An OSL press since the last typed character explains its layer.
5. **Two Pressed keys values added**: `Not shown · off in Paranoid` (Paranoid with OWNER_Q4 off) and `Not shown · the board isn't answering` (three failed reads, retrying). §5.6 lists neither case.
6. **A board that stopped answering is still asked every 2 s** while the lesson runs, showing Keymap only meanwhile, and Live · USB comes back on its own (§9.3 Errors); it shows nothing held while failed.
7. **A finished lesson waits for its last keystroke's evidence** (`settle()`, at most 250 ms, normally ε plus one sample) before it is saved. Keystrokes typed in that window are dropped, as they were during M1b's save.
8. **Wrong key**: a press is not wrong when it types the expected character, one just typed right (its sample came after its input), or the character after the expected one (a roll). Layer, Shift and tap-hold keys and keys that type nothing are never wrong.
9. **Live legends use the full effective mask**, not only default + top layer (`boardView` gained `displayedMask`), so transparency through a lower held layer shows the right legend.
10. **The sampler yields a task when a read returns within 1 ms** (only a mock or a stalled queue does that), so a synchronous mock can't starve the page. Real WebHID reads always yield.
11. **The lab's detail panel** shows the Lesson panel (the Practice nav item's panel); the lab is hidden and never linked, so it got no panel of its own.
12. **Layer reach and stray presses are computed but not shown**: `reach`/`target` are stored on keystroke events and `r` in results (§6.5), `strayEdges` and the mismatch counter exist and are tested; recording strays, the OS layout notice and the reach UI stay in M4 as §12 places them.
13. Spec line numbers are for `61db58a`; vLaunch2.2 moved code but nothing M2 uses (KeyboardContext's `pollMatrix` wrapper and 120 ms layer poll, `keyboardService.pollMatrix`/`getLayerStateMasks`) changed shape.

## Needs Mule testing

Use the Mule, never the daily-driver half.

1. **M0 numbers**: open `?practiceLab=1#practice/lab` on the test site or next, connect the Mule, type the prompt (about 500 characters, with `!` and other layer-1 symbols through the LT1 thumb for the roll rows), then **Copy results** into the PR. Check: samples/s (target ≥ 100), round trip, skew spread (ε = 40 ms should cover p95), taps caught, LT roll release→input near 0 ms (output on release), press edge − keydown (edges before their keydown mean a raw, pre-debounce read). Firmware load: while sampling, the typed text must match what was typed (no dropped keystrokes); "Presses with no character" should stay near 0 when typing carefully.
2. **Live lesson**: Practice → Lessons on the connected Mule: pill **Live · USB**; held keys dark; a wrong key red with `×`; holding MO(1) switches the board to layer 1; a lesson's result is saved with most hits observed (Progress shows no Inferred label for it once M4 adds those).
3. **Blur**: click away from the text mid-lesson; Matrix Tester-style reads must stop at once (the lab's rate drops to 0; or watch the board's held-key display freeze).
4. **Unplug** mid-lesson: the pill falls back to Keymap only and typing continues. **Replug**: click Connect; Practice reopens on Lessons with **Board connected · lesson restarted**, same profile.
5. **TG a layer** on the Mule mid-lesson: **Layer 1 is locked on** within about 300 ms; keystrokes ignored until it is off.
6. **Paranoid file** with the Mule: reads only while the lesson's text is focused and the window in front.
