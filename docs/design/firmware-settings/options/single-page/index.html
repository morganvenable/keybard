Firmware and Settings redesign · option

One Settings page

A single scrollable page with anchored sections. Every row is label left, control right, from one control set. Firmware sits at the top as a status row that expands into the install list. Version names are illustrative (vLaunch3 installed, vLaunch4 available) except where the first move off vLaunch2 is shown.

Round 2 · recommended. The page holds only app preferences and board/firmware management. Hardware, Typing, Pointing and Overlay left Settings for the main editor (settings-structure.md section 2), along with the Pointing panel's link row and Settings search. Groups are now "This keyboard / This browser / Keybard". The Firmware row shows status and the install list. Update opens the one-confirm sheet, then the update runs hands off (update-flow.md). Section 3 still shows round 1's in-row flow, kept only for reference.

  1. Backup is the first step, not a checkbox. It writes a "Before vLaunch4" snapshot and downloads the .svil. If it fails, the row turns amber with Update without backup beside Cancel (warn and allow, Q8).
  2. Advanced holds Right half only (Q9) and the release picker on next.keybard (vNext and vLaunch, Q5). Reinstall and Install from file live in the collapsed row's details (Q6, Q11).
  3. The chord diagram is drawn from the half with USB and names the two keys by their current legends; the code is the first 4 bytes of the manifest hash shown at ARM.
  4. The flow survives a reload. If the tab is reopened mid-update, the row opens on the step it was on (state in sessionStorage).
  5. Mixed halves (h) shows whenever presence reads "version differs", also outside an update (Q17), and replaces today's silent non-USB half.
