1. Getting there: the rail, the Settings home, and the update notice

About folds into Settings, so the footer is Quick Start, Manual, Settings. When Keybard carries a firmware newer than the board's, a dot on the Settings icon and a badge on the Keyboard row point at it (round 2 drops round 1's editor pill). The rail gains the two new editor homes, Typing behavior and Clusters. The canvas corner controls move to Editor.

2-3. Firmware: the update and its states

Round 1's update screens are gone from this option. The Keyboard page (section 4) shows what the board runs and the one install list. Its button opens the one-confirm sheet. Every firmware screen is drawn once, in flow/index.html, for all three layouts: the page states (D2, D2a-D2e), the sheet with the "Afterwards" choice (B1), the hands-off progress dialog with its single approval for both halves (U1-U5), and the result (A1).

6. Editor, About, Developer

Editor holds every preference that lives in this browser, with one control idiom per job: segmented for 2-4 options, a select for long lists, one switch style. Key size and panel position live only here (round 2: the corner controls go). Live/Manual stays in the toolbar only. About shows the real Keybard release; firmware detail moved to Firmware.
